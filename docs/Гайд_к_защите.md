# Гайд к защите проекта «Домашняя библиотека»

Это шпаргалка для тебя, а не для преподавателя. Здесь всё по порядку: как запустить и сдать проект, как устроен код, что происходит при нажатии каждой кнопки и что могут спросить на защите.

Совет: читай гайд, держа рядом открытый код. Найди каждый упомянутый кусок в файле глазами, так запомнится в разы лучше.

## Часть 1. Пошаговая инструкция: от архива до ссылки на Яндекс.Диске

### Шаг 1. Установи Python

1. Зайди на python.org, раздел Downloads, скачай Python 3.12 или 3.13 для Windows.
2. Запусти установщик. **Важно:** внизу первого окна поставь галочку **Add python.exe to PATH**. Без неё команды `python` и `pip` в консоли не заработают.
3. Нажми Install Now.
4. Проверка: нажми Win+R, введи `cmd`, нажми Enter. В чёрном окне набери:
   ```
   python --version
   ```
   Должно появиться что-то вроде `Python 3.12.7`. Если пишет «не является внутренней или внешней командой», значит галочку PATH не поставил: переустанови Python с галочкой.

### Шаг 2. Распакуй проект

1. Скачай `LibraryProject.zip`.
2. Правой кнопкой по нему, «Извлечь всё». Распакуй, например, в `C:\Projects\`.
3. Получится папка `C:\Projects\LibraryProject`, внутри `main.py`, `app`, `images`, `data` и т.д.

**Совет:** путь лучше делать без русских букв и пробелов. С PyInstaller так меньше сюрпризов.

### Шаг 3. Открой консоль в папке проекта

Самый простой способ: открой папку `LibraryProject` в проводнике, кликни в адресную строку сверху (где написан путь), сотри всё, напиши `cmd` и нажми Enter. Откроется консоль сразу в этой папке.

### Шаг 4. Установи библиотеки

```
pip install -r requirements.txt
```

Эта команда читает файл `requirements.txt` и ставит всё, что там перечислено: PyQt6 (окна и кнопки) и PyInstaller (сборщик exe). Подожди, пока закончится, займёт минуту-две.

### Шаг 5. Запусти программу из кода

```
python main.py
```

Появится заставка, потом главное окно с 16 книгами-примерами. Рядом с `main.py` появится файл `library.db`, это и есть база данных.

Если что-то сломается, программа покажет окно с текстом ошибки (так специально сделано в `main.py`, об этом ниже).

### Шаг 6. Собери exe

Дважды кликни по файлу `build_exe.bat` (или напиши его имя в консоли). Внутри него одна команда PyInstaller. Сборка идёт 1-3 минуты, в конце напишет «Готово!».

После сборки появятся:
- папка `build`: временный мусор сборщика, можно удалить;
- файл `LibraryApp.spec`: настройки сборки, тоже можно удалить;
- папка `dist`, в ней **`LibraryApp.exe`**. Вот он, единый исполняемый файл.

### Шаг 7. Проверь exe

1. Скопируй `LibraryApp.exe` в любую пустую папку, например на рабочий стол в папку `test`.
2. Запусти. Первый запуск может занять 5-10 секунд: exe распаковывает себя во временную папку.
3. Рядом с exe должен появиться `library.db`. Значит всё работает.

Если Windows покажет синее окно «Windows защитила ваш компьютер», нажми «Подробнее», затем «Выполнить в любом случае». Так бывает со всеми самодельными exe, у которых нет цифровой подписи. Антивирус тоже иногда ругается на exe от PyInstaller. Это ложная тревога, преподаватели про это знают.

### Шаг 8. Упакуй проект для сдачи

1. Удали папку `build`, файл `LibraryApp.spec` и `library.db` (база создастся заново при запуске, а лишние тестовые данные сдавать незачем).
2. Папку `dist` с exe оставь, пусть преподаватель сразу видит готовый файл.
3. Правой кнопкой по папке `LibraryProject`: «Отправить», затем «Сжатая ZIP-папка». Получится `LibraryProject.zip`.

### Шаг 9. Залей на Яндекс.Диск и получи ссылку

1. Зайди на disk.yandex.ru (нужен Яндекс-аккаунт).
2. Кнопка «Загрузить» слева сверху, выбери свой zip.
3. Когда загрузится, правой кнопкой по файлу, «Поделиться». Яндекс сразу скопирует ссылку вида `https://disk.yandex.ru/d/...`.
4. Открой эту ссылку в режиме инкогнито (Ctrl+Shift+N), чтобы убедиться, что она открывается без входа в аккаунт.
5. Отправь ссылку преподавателю и прикрепи её как решение задачи.

```
│   ├── stats_widget.py     вкладка «Статистика»

```

### Главная идея архитектуры (запомни её, это любят спрашивать)

Код разделён на две части:

1. **Работа с данными** живёт только в `database.py`. Там все SQL-запросы. Окна ни разу не пишут SQL сами.
2. **Интерфейс** (окна, кнопки, таблицы) лежит во всех остальных файлах. Когда окну нужны данные, оно зовёт метод базы, например `self.db.books()` или `self.db.add_book(...)`.

Зачем так: если завтра захочется поменять SQLite на другую базу, переписывать придётся только один файл. И код читается проще: открыл `database.py`, видишь всю логику данных в одном месте.

Объект базы создаётся **один раз** в `main.py` и передаётся во все окна через параметр `db`. Поэтому почти у каждого окна в `__init__` есть `self.db = db`.

## Часть 3. Разбор кода по файлам

### 3.1. `main.py`: с чего всё начинается

Когда пишешь `python main.py`, выполняется функция `main()`. По шагам:

```python
sys.excepthook = excepthook
```
Подменяем обработчик ошибок. Обычно, если в программе с окнами случается ошибка, exe просто молча закрывается и ты не понимаешь почему. Наша функция `excepthook` ловит любую непойманную ошибку и показывает её в окне `QMessageBox.critical`.

```python
app = QApplication(sys.argv)
app.setStyle("Fusion")
```
`QApplication` это «сердце» любой программы на PyQt. Без него нельзя создать ни одного окна. Он один на всю программу. `Fusion` это стиль оформления, одинаково выглядящий на всех системах.

```python
QLocale.setDefault(QLocale(QLocale.Language.Russian, QLocale.Country.Russia))
translator = QTranslator(app)
if translator.load("qtbase_ru", ...):
    app.installTranslator(translator)
```
Включаем русский язык. Без этого в стандартных диалогах кнопки были бы Yes/No/Cancel, а в календаре Mon/Tue. `qtbase_ru` это файл перевода, который идёт вместе с PyQt6.

```python
splash = QSplashScreen(QPixmap(image("splash.png")))
splash.show()
```
Показываем заставку (картинку без рамки окна), пока грузится база.

```python
db = Database(DB_PATH)
if db.is_empty():
    db.import_csv(resource_path("data", "books_sample.csv"))
```
Открываем базу. Если файла не было, SQLite создаст его сам. Если книг ноль (первый запуск), загружаем примеры из CSV, чтобы программа не была пустой. Всё это обёрнуто в `try/except`: если база не открылась (например, папка только для чтения), покажем ошибку и выйдем.

```python
window = MainWindow(db)
QTimer.singleShot(1200, lambda: (window.show(), splash.finish(window)))
code = app.exec()
```
Создаём главное окно. `QTimer.singleShot(1200, ...)` значит «через 1200 миллисекунд (1,2 секунды) выполни это»: покажи окно и убери заставку. Задержка нужна просто чтобы заставку успели увидеть.

`app.exec()` это **главный цикл событий**. Программа «зависает» на этой строчке и ждёт действий пользователя: кликов, нажатий клавиш. Каждое действие превращается в событие, Qt вызывает нужную функцию. Цикл заканчивается, когда закрыли последнее окно. Потом закрываем базу и выходим.

### 3.2. `app/paths.py`: где лежат файлы

Проблема: программа запускается двумя способами.
- `python main.py`: картинки лежат рядом в папке `images`.
- `LibraryApp.exe`: PyInstaller упаковал картинки **внутрь** exe. При запуске exe распаковывает их во временную папку, и путь к ней лежит в `sys._MEIPASS`.

```python
def resource_path(*parts):
    base = getattr(sys, "_MEIPASS", PROJECT_DIR)
    return os.path.join(base, *parts)
```
`getattr(sys, "_MEIPASS", PROJECT_DIR)` значит «возьми `sys._MEIPASS`, а если такого нет (запуск не из exe), возьми папку проекта». Так один и тот же код находит картинки в обоих случаях.

```python
def user_dir():
    if getattr(sys, "frozen", False):
        return os.path.dirname(sys.executable)
    return PROJECT_DIR
```
А вот базу во временную папку класть нельзя: она удаляется после закрытия программы, и все книги пропадут. Поэтому база и обложки хранятся **рядом с exe**. `sys.frozen` равно True только в собранном exe, `sys.executable` это путь к самому exe.

`icon("add")` и `image("logo.png")` просто короткие функции, чтобы не писать каждый раз длинный путь.

### 3.3. `app/database.py`: база данных

#### Таблицы

Пять таблиц, создаются командой `CREATE TABLE IF NOT EXISTS` (то есть «создай, если ещё нет»; при повторном запуске ничего не сломается):

| Таблица | Что хранит | Поля |
|---|---|---|
| `genres` | жанры | id, name |
| `authors` | авторы | id, name, country, birth_year |
| `books` | книги | id, title, **author_id**, **genre_id**, year, pages, rating, status, favorite, cover, notes, added |
| `readings` | журнал чтения | id, **book_id**, date, pages |
| `settings` | настройки | key, value |

Связи (это внешние ключи, `REFERENCES`):
- `books.author_id` указывает на `authors.id`;
- `books.genre_id` указывает на `genres.id`;
- `readings.book_id` указывает на `books.id`.

То есть в книге не пишется имя автора текстом, а хранится номер автора. Зачем: если переименовать автора, он переименуется сразу во всех его книгах. И не будет «Пушкин» в одной книге и «А. С. Пушкин» в другой.

Что происходит при удалении:
- `ON DELETE SET NULL` у автора и жанра: удалил автора, у его книг `author_id` станет пустым («автор не указан»), а сами книги останутся.
- `ON DELETE CASCADE` у журнала: удалил книгу, все записи журнала чтения по ней удалятся автоматически.

`PRAGMA foreign_keys = ON`: в SQLite проверка связей по умолчанию **выключена**, эта строчка её включает. Без неё CASCADE и SET NULL не работали бы.

`UNIQUE` у имени автора и жанра: нельзя завести двух одинаковых. Если попробовать, SQLite выбросит ошибку `sqlite3.IntegrityError`, а окна её ловят и пишут «Такой автор уже есть».

#### Подключение

```python
self.con = sqlite3.connect(path)
self.con.row_factory = sqlite3.Row
```
`sqlite3.Row` позволяет обращаться к полям по имени: `book["title"]` вместо `book[1]`. Удобнее и понятнее.

#### Чтение (SELECT)

Самый важный запрос, `BOOK_SELECT`:
```sql
SELECT b.*, IFNULL(a.name, '') AS author, IFNULL(g.name, '') AS genre,
       IFNULL((SELECT SUM(r.pages) FROM readings r WHERE r.book_id = b.id), 0) AS read_pages
FROM books b
LEFT JOIN authors a ON a.id = b.author_id
LEFT JOIN genres g ON g.id = b.genre_id
```
Разбираем:
- `b`, `a`, `g` это короткие псевдонимы таблиц.
- `LEFT JOIN authors` значит «приклей к каждой книге её автора». **LEFT** важно: если у книги автора нет, книга всё равно попадёт в результат (с обычным JOIN она бы пропала).
- `IFNULL(a.name, '')`: если автора нет, вместо NULL подставь пустую строку.
- Подзапрос `(SELECT SUM(r.pages) ...)` считает, сколько страниц книги прочитано по журналу. Мы **не храним** прогресс отдельно, а каждый раз считаем. Поэтому он никогда не разойдётся с журналом.

Метод `books(text, genre_id, status, favorites)` собирает условие WHERE по кусочкам: если в поиске что-то написано, добавляет `b.title LIKE ?`; если выбран жанр, добавляет `b.genre_id = ?` и так далее. Потом склеивает через `AND`.

`LIKE '%Толст%'` значит «содержит Толст где угодно». `%` означает «любые символы».

#### Почему везде знаки вопроса `?`

```python
self.con.execute("DELETE FROM books WHERE id = ?", (book_id,))
```
Значения никогда не вклеиваются в SQL строкой, а передаются отдельно. Это защита от **SQL-инъекций**: если пользователь введёт в название что-то вроде `'); DROP TABLE books; --`, это будет просто странное название, а не команда. Это очень частый вопрос на защите.

В `add_book` используются именованные параметры `:title`, `:pages` и т.д. Это то же самое, только значения берутся из словаря по имени.

#### Запись, изменение, удаление

- `add_book`, `add_author`, `add_genre`, `add_reading`: `INSERT INTO ...`
- `update_book`, `update_author`, `rename_genre`, `set_status`, `set_favorite`: `UPDATE ... SET ... WHERE id = ?`
- `delete_book`, `delete_author`, `delete_genre`, `delete_reading`: `DELETE FROM ... WHERE id = ?`

После каждого изменения вызывается `self.con.commit()`. Без commit изменения не сохранятся в файл.

`cur.lastrowid` это id только что добавленной записи. Нужен, например, чтобы после добавления книги сразу выделить её в таблице.

#### Статистика

- `count_by_status`: `GROUP BY status` считает, сколько книг в каждом статусе.
- `count_by_genre`: то же по жанрам, для диаграммы.
- `pages_by_month(year)`: `substr(date, 6, 2)` вырезает месяц из даты вида `2026-11-05` (символы 6 и 7, то есть `11`), группирует по месяцам и суммирует страницы. Получается список из 12 чисел.

#### Настройки

```sql
INSERT OR REPLACE INTO settings(key, value) VALUES (?, ?)
```
«Вставь, а если такой ключ уже есть, замени». Так хранятся цель на год, шрифт и цвет.

#### CSV

`import_csv`: открывает файл, `csv.DictReader` читает каждую строку как словарь `{"title": ..., "author": ...}`. Разделитель `;`, потому что русский Excel по умолчанию использует точку с запятой. Для автора и жанра вызываются `author_id(name)` и `genre_id(name)`: они ищут по имени, а если не нашли, создают. Кодировка `utf-8-sig`, чтобы Excel правильно показал русские буквы.

`export_csv` делает обратное: `csv.writer` пишет заголовок и строку на каждую книгу.

Функция `_int` превращает текст в число, а если не получилось (пусто или мусор), возвращает 0. Чтобы кривой CSV не ронял программу.

### 3.4. Главное про PyQt: сигналы и слоты

Это основа всего интерфейса, разберись обязательно.

- **Сигнал** это событие, которое испускает виджет: кнопку нажали (`clicked`), текст поменялся (`textChanged`), выбрали другой пункт (`currentIndexChanged`).
- **Слот** это функция, которая должна выполниться в ответ.
- `.connect()` их связывает.

```python
self.search_edit.textChanged.connect(self.refresh_books)
```
Читается так: «когда текст в поиске изменился, вызови `refresh_books`». Поэтому поиск работает сразу при наборе, без кнопки «Найти».

**Layout** (компоновка): `QVBoxLayout` ставит виджеты столбиком, `QHBoxLayout` в ряд, `QFormLayout` парами «подпись: поле». Благодаря им окна правильно растягиваются, ничего не съезжает.

**Диалоги**: у окна вызывается `.exec()`, программа ждёт, пока его закроют. Если закрыли через `accept()` (кнопка «Сохранить»), `exec()` вернёт «принято», если через `reject()` («Отмена»), вернёт «отклонено». Главное окно смотрит на это и решает, обновлять таблицу или нет.

### 3.5. `app/main_window.py`: главное окно

Класс `MainWindow` наследуется от `QMainWindow`. Это специальный вид окна, у которого уже есть места под меню, панель инструментов, центральный виджет и строку состояния.

#### Конструктор `__init__`

По очереди вызывает:
1. `_create_actions()`: создаёт **действия** (`QAction`). Действие это команда с текстом, иконкой, горячей клавишей и функцией. Одно и то же действие вставляется и в меню, и на панель инструментов, и в контекстное меню. Нажмёшь где угодно, выполнится одна функция.
   ```python
   self.act_add = self._action("Добавить книгу", "add", self.add_book, "Ctrl+N")
   ```
2. `_create_menu()`: строка меню Файл / Книги / Справочники / Вид / Справка.
3. `_create_toolbar()`: панель с большими иконками.
4. `_create_central()`: всё, что в середине.
5. `apply_accent()`: красит заголовки таблицы в выбранный цвет.
6. `refresh_all()`: загружает данные из базы.

#### Как устроена середина окна

`QSplitter` делит окно на три части, границы которых можно двигать мышкой:
- **Слева** фильтры (`_create_filters`): поле поиска `QLineEdit`, список жанров `QComboBox`, переключатели статуса `QRadioButton` в рамке `QGroupBox`, флажок `QCheckBox` «Только любимые», кнопка сброса, цитата дня.
- **В центре** вкладки `QTabWidget`: «Книги» (таблица), «Статистика», «Календарь чтения».
- **Справа** карточка книги (`_create_preview`): обложка, звёзды, полоса прогресса, заметки.

Переключатели статуса собраны в `QButtonGroup`, у каждого свой номер: 0 «Все», 1 «Хочу прочитать», 2 «Читаю», 3 «Прочитано». В `current_filters` номер превращается в текст статуса: `STATUSES[status_id - 1]`.

**Цитата дня**: `load_quotes()` читает `data/quotes.txt` построчно, `random.choice` выбирает случайную. Это то самое использование txt-файла.

#### Заполнение таблицы, `refresh_books`

1. Запоминает, какая книга была выделена.
2. Берёт фильтры и просит у базы книги: `self.db.books(**self.current_filters())`. Две звёздочки `**` раскладывают словарь в именованные параметры.
3. **Выключает сортировку** на время заполнения. Иначе при включённой сортировке строки перескакивают прямо во время вставки и данные перемешиваются. Классическая ловушка `QTableWidget`.
4. Для каждой книги создаёт ячейки `QTableWidgetItem` и ставит их через `setItem(row, col, item)`.
5. Считает процент: прочитанные страницы делить на все, умножить на 100, не больше 100. Если статус «Прочитано», всегда 100%.
6. **Прячет id книги** в ячейку с названием: `title.setData(Qt.ItemDataRole.UserRole, b["id"])`. Пользователь id не видит, но программа всегда знает, какая книга в какой строке. `UserRole` это «служебная ячейка для своих данных».
7. Включает сортировку обратно, возвращает выделение, пишет в строке состояния «Показано книг: N».

**`NumItem`**: обычная ячейка сортирует как текст, и тогда «1300» окажется меньше «328» (сравнение идёт по первой цифре). `NumItem` переопределяет `__lt__` (оператор «меньше») и сравнивает настоящие числа.

#### Какая книга выбрана: `selected_id`

Берёт текущую строку, из второго столбца достаёт спрятанный id. Все действия (изменить, удалить, журнал) начинаются с этого. Если ничего не выбрано, `need_book` показывает «Сначала выберите книгу».

#### Карточка справа: `update_preview`

Привязана к сигналу `itemSelectionChanged`: выделил другую строку, карточка обновилась. Берёт книгу из базы по id и заполняет обложку, звёзды, прогресс, заметки.

#### Календарь

`refresh_calendar` берёт из базы все даты, когда что-то читалось (`reading_dates`), и через `setDateTextFormat` красит их жирным с фоном. Сначала сбрасывает старую подсветку (`QDate()` значит «для всех дат»). При выборе дня (`selectionChanged`) `refresh_day` показывает в списке справа, что читалось в этот день.

#### Действия

- `add_book`: открывает `BookDialog` без id (значит новая книга). Если сохранили, обновляет всё и выделяет новую книгу.
- `edit_book`: то же, но с id (значит редактирование).
- `delete_book`: спрашивает подтверждение `QMessageBox.question` («Да» / «Нет», по умолчанию «Нет», чтобы случайный Enter ничего не удалил), потом `db.delete_book`.
- `open_readings`: открывает журнал чтения.
- `toggle_favorite`: переворачивает флажок любимой книги (`not` от текущего значения).
- `context_menu`: меню по правой кнопке мыши, `QMenu`. Подменю «Статус» строится циклом. Там есть хитрость `lambda s=s:`: без `s=s` все пункты получили бы последний статус из цикла, потому что лямбда запоминает переменную, а не её значение на момент создания.

#### Файлы

- `import_csv`: `QFileDialog.getOpenFileName` показывает стандартное окно выбора файла. Если выбрали, вызывает `db.import_csv`, ошибки ловит и показывает.
- `export_csv`: `QFileDialog.getSaveFileName`, окно «Сохранить как». Экспортирует книги **с учётом текущих фильтров**.
- `save_report`: собирает список строк (статистика + все книги) и записывает в txt-файл.

#### Вид

- `choose_font`: `QFontDialog.getFont`, стандартный диалог выбора шрифта. Шрифт применяется к таблице и сохраняется в базу как строка (`font.toString()`). При следующем запуске читается обратно (`fromString`).
- `choose_color`: `QColorDialog.getColor`, стандартный выбор цвета. Цвет сохраняется в настройки, `apply_accent` применяет его через **таблицу стилей** (`setStyleSheet`, похоже на CSS из веба) к заголовкам таблицы и полосам прогресса, а также к диаграммам.

#### Закрытие

`closeEvent` это функция, которую Qt вызывает при попытке закрыть окно. Мы спрашиваем «Закрыть программу?». `event.accept()` закрывает окно, `event.ignore()` отменяет закрытие.

### 3.6. `app/book_dialog.py`: окно книги

Класс `BookDialog(QDialog)`. Если передан `book_id`, это редактирование, иначе добавление.

Виджеты:
- `QLineEdit`: название;
- `QComboBox`: автор и жанр, рядом `QToolButton` с плюсиком для добавления нового;
- `QSpinBox`: год и страницы. `setSpecialValueText("—")`: когда значение 0, показывается прочерк;
- `QSlider`: оценка от 0 до 5, рядом `QLabel` со звёздами, обновляется по сигналу `valueChanged`;
- `QComboBox`: статус;
- `QCheckBox`: любимая;
- `QPlainTextEdit`: заметки;
- `CoverLabel`: обложка;
- `QDialogButtonBox`: кнопки «Сохранить» и «Отмена».

**Хитрость с комбобоксами**: `addItem(a["name"], a["id"])`. Пользователь видит имя, а к пункту привязан id. `currentData()` возвращает id выбранного. Первый пункт «не указан» с данными `None`, он в базу запишется как NULL.

**Плюсик у автора** открывает маленькое окно `AuthorEditDialog`, **плюсик у жанра** открывает `QInputDialog.getText`, стандартное окошко с одним полем ввода. После добавления список перезагружается и новый пункт сразу выбирается.

**Обложка, `choose_cover`**: `QFileDialog` выбирает картинку, потом файл **копируется** в папку `covers` под случайным именем (`uuid`). Зачем копировать: если хранить путь к оригиналу, а ты его потом удалишь или переместишь, обложка пропадёт. Случайное имя нужно, чтобы две картинки `cover.jpg` не перезаписали друг друга.

**`save`**: собирает всё в словарь (`data()`), проверяет, что название не пустое (иначе предупреждение и курсор в поле названия), и вызывает `update_book` или `add_book`. В конце `self.accept()` закрывает окно с результатом «принято».

### 3.7. `app/author_dialog.py`: справочники

**`AuthorEditDialog`**: маленькая форма ФИО / страна / год. Проверяет, что имя введено. `values()` возвращает три значения.

**`AuthorsDialog`**: таблица авторов, которую **можно редактировать прямо в ячейках** (двойной клик по ячейке). Это изменение данных в БД в чистом виде.

Как работает: сигнал `itemChanged` срабатывает, когда ячейку изменили, и вызывает `item_changed`. Та читает всю строку, проверяет (имя не пустое, год состоит из цифр) и вызывает `db.update_author`.

Подвох и как он решён: `itemChanged` срабатывает и тогда, когда **программа сама** заполняет таблицу в `load()`. Чтобы при загрузке не было сотни лишних сохранений, есть флажок `self.loading`: пока он True, `item_changed` сразу выходит.

Столбец «Книг» сделан нередактируемым: `item.flags() & ~Qt.ItemFlag.ItemIsEditable`. Это побитовая операция «убери флаг редактируемости».

**`GenresDialog`**: список жанров `QListWidget`. Добавление и переименование через `QInputDialog`, удаление с подтверждением. Двойной клик по жанру тоже переименовывает.

### 3.8. `app/reading_dialog.py`: журнал чтения

Вверху обложка, название и `QProgressBar` с форматом `"%v из %m стр. (%p%)"`: `%v` текущее значение, `%m` максимум, `%p` проценты. Qt подставляет их сам.

Новая запись: `QDateEdit` (дата с выпадающим календариком, нельзя выбрать будущее, `setMaximumDate`), `QSpinBox` со страницами и `QDial` (крутилка). Крутилка и поле связаны в обе стороны: крутишь крутилку, меняется число, и наоборот.

`add_record`:
1. сохраняет запись в базу (`add_reading`);
2. перезагружает таблицу и считает сумму страниц;
3. если книга была «Хочу прочитать», автоматически ставит «Читаю»;
4. если прочитано страниц не меньше, чем в книге, спрашивает, отметить ли её прочитанной.

Даты в базе хранятся как `2026-11-05` (формат ISO). Так они правильно сортируются как текст и по ним удобно искать год (`LIKE '2026-%'`). На экране они показываются как `05.11.2026`.

### 3.9. `app/stats_widget.py`: статистика

- Цель на год: `QSpinBox` с годом и целью в страницах, `QProgressBar` показывает выполнение. Цель сохраняется в таблицу `settings` при каждом изменении.
- Две диаграммы `BarChart`: книги по жанрам (первые 8) и страницы по месяцам.

`refresh()` берёт свежие данные из базы и раскладывает по виджетам. Вызывается при переключении вкладок и после любых изменений.

### 3.10. `app/widgets.py`: самодельные виджеты

Это и есть «дополнительные виджеты», которых нет в стандартном наборе.

**`CoverLabel`**: `QLabel` с картинкой обложки. Функция `cover_pixmap` ищет файл; если не нашла, берёт заглушку `no_cover.png`. `scaled(..., KeepAspectRatio, SmoothTransformation)` уменьшает картинку без искажения пропорций и со сглаживанием.

**`StarRating`** и **`BarChart`** рисуются вручную. У любого виджета есть метод `paintEvent`, который Qt вызывает, когда виджет нужно перерисовать. Внутри создаём `QPainter` (кисточку) и рисуем: `drawText`, `drawRoundedRect` и т.д. Чтобы перерисовать с новыми данными, вызывается `self.update()`: он просит Qt вызвать `paintEvent` при ближайшей возможности.

Как считается диаграмма:
- находим максимум среди значений;
- высота столбика равна `высота_области * значение / максимум`, то есть самый большой столбик во всю высоту, остальные пропорционально;
- ширина области делится на число столбиков (`step`), сам столбик занимает 65% от этого шага, остальное отступы;
- подписи снизу обрезаются многоточием, если не помещаются (`elidedText`).

### 3.13. Сборка: `build_exe.bat`

```
pyinstaller --noconfirm --clean --onefile --windowed --name LibraryApp --icon images\app.ico --add-data "images;images" --add-data "data;data" main.py
```
- `--onefile`: всё в **один** exe (иначе была бы папка с кучей файлов);
- `--windowed`: без чёрного окна консоли;
- `--name LibraryApp`: имя файла;
- `--icon`: иконка exe;
- `--add-data "images;images"`: положить папку `images` внутрь exe. PyInstaller сам видит только код, картинки и CSV надо указывать явно. На Windows разделитель `;`, на Linux `:`;
- `main.py`: с чего начинать.

PyInstaller берёт Python, PyQt6, весь наш код и данные, сжимает в один файл. При запуске exe распаковывает себя во временную папку (`sys._MEIPASS`) и запускает `main.py`. Поэтому первый запуск чуть медленнее.

## Часть 4. Что происходит при нажатии кнопок (цепочки)

### «Добавить книгу»

1. Клик по кнопке, срабатывает `QAction` `act_add`, вызывается `MainWindow.add_book`.
2. Создаётся `BookDialog(self.db)` без id. В конструкторе заполняются списки авторов и жанров из базы (`db.authors()`, `db.genres()`).
3. `dlg.exec()` показывает окно, программа ждёт.
4. Пользователь заполняет поля и жмёт «Сохранить», вызывается `BookDialog.save`.
5. `save` проверяет название, вызывает `db.add_book(data)`, а там `INSERT INTO books` и `commit`.
6. `self.accept()` закрывает окно, `exec()` возвращает «принято».
7. Главное окно вызывает `refresh_all()`: перезагружает фильтр жанров, таблицу, статистику и календарь.
8. `select_id(dlg.book_id)` выделяет новую книгу.

### Поиск

1. Вводишь букву, сигнал `textChanged`, вызывается `refresh_books`.
2. `current_filters()` собирает текст, жанр, статус, флажок.
3. `db.books(...)` строит SQL с `WHERE ... LIKE ?` и возвращает подходящие книги.
4. Таблица заполняется заново.

### Удалить книгу

1. `delete_book`, `need_book` берёт id выделенной строки.
2. `QMessageBox.question` спрашивает подтверждение.
3. При «Да» вызывается `db.delete_book`, а там `DELETE FROM books WHERE id = ?`. Благодаря CASCADE удаляются и записи журнала.
4. `refresh_all()`.

### Изменение автора в справочнике

1. Двойной клик по ячейке, правка, Enter.
2. Сигнал `itemChanged`, вызывается `item_changed`.
3. Проверка, затем `db.update_author`, а там `UPDATE authors SET ...`.
4. После закрытия справочника главное окно делает `refresh_all()`, и новое имя видно во всех книгах этого автора (потому что книги хранят id, а не имя).

## Часть 6. Что могут спросить на защите и что ответить

**Почему SQLite, а не просто файл?**
SQLite это полноценная база в одном файле, ничего ставить не надо, модуль `sqlite3` встроен в Python. Есть связи между таблицами, проверка уникальности, быстрый поиск и подсчёт статистики одним запросом.

**Зачем несколько таблиц, почему не одна?**
Чтобы не дублировать данные. Автор хранится один раз, книги ссылаются на него по id. Переименовал автора, он поменялся во всех книгах. Это называется нормализация.

**Что такое внешний ключ?**
Поле, которое хранит id записи из другой таблицы. `books.author_id` хранит id из `authors`.

**Что будет, если удалить автора, у которого есть книги?**
Книги останутся, у них автор станет «не указан». Так работает `ON DELETE SET NULL`. А при удалении книги её журнал чтения удаляется сам (`ON DELETE CASCADE`).

**Почему в запросах знаки вопроса?**
Это параметризованные запросы, защита от SQL-инъекций. Значения передаются отдельно от текста запроса, поэтому их нельзя «выполнить» как SQL-команду.

**Что такое LEFT JOIN и почему не просто JOIN?**
JOIN склеивает строки двух таблиц по условию. LEFT JOIN оставляет книгу, даже если у неё нет автора или жанра. С обычным JOIN такие книги пропали бы из списка.

**Как хранится прогресс чтения?**
Не хранится, считается на лету: сумма страниц из журнала по этой книге (подзапрос с `SUM`). Поэтому он всегда совпадает с журналом.

**Что такое сигналы и слоты?**
Сигнал это событие (нажатие кнопки, изменение текста), слот это функция, которая на него реагирует. Связываются через `connect`. Пример: `search_edit.textChanged.connect(self.refresh_books)`.

**Что делает `app.exec()`?**
Запускает цикл обработки событий. Программа ждёт действий пользователя и вызывает нужные функции, пока не закроют главное окно.

**Зачем `UserRole` в таблице?**
Чтобы спрятать в ячейку id книги. Пользователь его не видит, а программа по нему понимает, с какой книгой работать.

**Почему сортировка отключается при заполнении таблицы?**
Если она включена, строки переставляются прямо во время вставки и ячейки разных книг перемешиваются.

**Зачем свой класс `NumItem`?**
Обычная ячейка сортирует как текст: «1300» оказалось бы меньше «328». `NumItem` сравнивает числа.

**Как нарисованы диаграммы?**
Вручную, в методе `paintEvent` через `QPainter`. Высота столбика пропорциональна значению относительно максимума.

**Как программа находит картинки внутри exe?**
PyInstaller распаковывает их во временную папку, путь лежит в `sys._MEIPASS`. Функция `resource_path` берёт его, а при обычном запуске берёт папку проекта.

**Почему база лежит рядом с exe, а не внутри?**
Внутренняя временная папка удаляется после закрытия, и все данные пропали бы. А рядом с exe база сохраняется между запусками.

**Зачем копировать обложку в папку covers?**
Чтобы обложка не пропала, если пользователь удалит или переместит исходную картинку.

**Зачем `commit()`?**
Без него изменения остаются в памяти и не записываются в файл базы.

**Зачем `try/except` при импорте CSV?**
Файл может быть битым, в другой кодировке или недоступен. Без обработки программа бы упала, а так показывает понятную ошибку.

**Почему CSV через точку с запятой?**
Так его правильно откроет русский Excel. Кодировка `utf-8-sig`, чтобы в Excel не было кракозябр вместо русских букв.

**Что сложнее всего было сделать?**
Можно ответить честно про что-то конкретное: например, сборку в exe (пути к картинкам и место для базы) или справочник авторов с правкой прямо в ячейках, где пришлось отключать сохранение во время загрузки таблицы.

**Что бы ты добавил?**
Поиск обложек в интернете, резервную копию базы одной кнопкой, учёт книг, которые дал почитать друзьям.

## Часть 8. Словарик

- **Виджет**: любой элемент интерфейса: кнопка, поле, таблица, даже целое окно.
- **Layout (компоновка)**: невидимая сетка, которая расставляет виджеты и растягивает их вместе с окном.
- **Сигнал / слот**: событие и функция-реакция на него.
- **Диалог (QDialog)**: отдельное окно, которое открывается поверх основного и ждёт ответа.
- **Модальное окно**: пока оно открыто, с главным окном работать нельзя (так работает `exec()`).
- **QPainter**: «кисточка» для рисования на виджете или картинке.
- **paintEvent**: метод, который Qt вызывает, когда виджет нужно перерисовать.
- **SQL**: язык запросов к базе. SELECT читает, INSERT добавляет, UPDATE меняет, DELETE удаляет.
- **Первичный ключ (PRIMARY KEY)**: уникальный номер записи (`id`).
- **Внешний ключ (REFERENCES)**: поле, ссылающееся на id в другой таблице.
- **AUTOINCREMENT**: id назначается сам, по возрастанию.
- **JOIN**: склейка строк из двух таблиц.
- **GROUP BY**: группировка строк для подсчёта (сколько книг в каждом жанре).
- **commit**: сохранить изменения в файл базы.
- **CSV**: таблица в текстовом файле, значения через разделитель.
- **PyInstaller**: программа, которая упаковывает Python-проект в exe.
- **requirements.txt**: список библиотек, нужных проекту; ставятся одной командой `pip install -r requirements.txt`.
